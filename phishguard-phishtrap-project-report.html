Abstract — PhishGuard is a browser-integrated phishing detection system that combines rule-based URL analysis, real-time blocklist matching, and deception technology to protect users from phishing attacks. Unlike existing tools that merely block suspicious URLs without explanation, PhishGuard provides explainable threat scores with human-readable detection signals, MITRE ATT&CK tags, and a unique PhishTrap honeytoken system that allows users to counter-track attackers. All processing occurs locally — no user data is sent to any external server.

1. Problem Statement

Phishing remains one of the most prevalent and effective forms of cybercrime. Existing browser protection tools have three critical shortcomings:

  • Black-box blocking — tools block URLs but do not explain why, leaving users unable to make informed decisions
  • Reactive detection — users only discover a site was phishing after clicking, often after credentials are already compromised
  • No attacker tracing — there is no mechanism to identify or track the attacker who deployed the phishing site
⚠️ Gap: No existing consumer tool combines explainable scoring + pre-emptive scanning + deception-based attacker tracing in a single privacy-preserving browser extension.

2. Objectives

Primary

  • Real-time phishing detection on link hover and page load
  • Explainable threat scores with per-rule weights
  • Overlay card with Safe / Suspicious / Dangerous verdict
  • Block dangerous navigations before credentials are entered

Secondary

  • PhishTrap: plant honeytoken fake credentials on phishing sites
  • Tripwire alerts when attacker reuses stolen honeytoken
  • In-extension dashboard with scan history and token table
  • 100% local — zero cloud dependency, full privacy

4. Detection Engine

The detection engine in rules.py applies 10 weighted rules to each URL. Scores are additive and capped at 100.

False Positive Mitigations

  • Query string exclusion — keyword matching and URL length rules operate on host+path only; UTM tracking parameters (utm_source, utm_medium) are ignored
  • Trusted domain allowlist — 20+ major domains (Google, Microsoft, Apple, Amazon, etc.) are exempt from keyword rules
  • Brand name removal — generic brand names removed from keyword list; only action words (login, verify, suspended) are matched

9. Key Design Decisions

Shadow DOM for Overlay

The overlay card is injected inside a Shadow DOM root, making it completely isolated from the host page's CSS and JavaScript. This prevents phishing sites from hiding or styling the warning card through their own stylesheets.

Explainable Over Black-Box

Every detection signal is surfaced to the user with its contribution score (e.g., "Phishing keyword in URL (+8)"). This builds user trust and teaches recognition of phishing patterns — a black-box "Blocked" message does neither.

Privacy-First Architecture

✅ Zero cloud dependency. All URL analysis, scan history, and honeytoken data is stored locally. The only external request is the hourly OpenPhish feed refresh. No user browsing data is ever transmitted to a remote server.

Debounced Hover Pre-scan

Link hovering triggers a background cache-warming scan after 150ms (cancelled if the user moves away). By the time the user clicks, the result is already cached — the overlay appears in <50ms perceived latency.

11. Ethics & Responsible Use

  • No real credentials captured — PhishTrap uses only system-generated fake credentials; no real user passwords are ever stored or transmitted
  • No surveillance — all scan data is stored locally; no URL history is sent to any external service
  • Testing scope — tested only against PhishTank-reported URLs and locally hosted dummy phishing pages
  • User consent — every blocking action and PhishTrap activation requires explicit user interaction
  • No legal gray area — honeytokens planted on phishing sites constitute defensive deception, not hacking; the user only submits credentials to a site already identified as malicious

12. Limitations & Future Work

Current Limitations

  • Backend must run locally (no cloud deployment)
  • Rule-based only — no ML model for zero-day phishing
  • No WHOIS domain age check (requires external API)
  • PhishTrap tripwire relies on attacker reusing credentials at the same /decoy-login endpoint

Future Enhancements

  • WHOIS domain age integration (new domains = higher risk)
  • ML model trained on PhishTank dataset
  • Screenshot-based visual similarity detection
  • External Canarytokens.org integration for out-of-band tripwire
  • Cross-browser support (Firefox WebExtension)

13. Conclusion

PhishGuard successfully demonstrates a privacy-preserving, explainable phishing detection system that goes beyond simple URL blocking. By combining a weighted rule engine, real-time blocklist integration, Shadow DOM overlay UI, and honeytoken-based deception technology, it addresses all three core gaps identified in existing tools: lack of explanation, reactive detection, and no attacker tracing.

The PhishTrap component in particular represents a novel application of deception technology at the consumer browser level — transforming users from passive victims into active participants who can counter-track attackers. All of this is achieved with zero cloud dependency, ensuring complete user privacy.

Key takeaway: Phishing defence does not require surrendering privacy to a cloud service. A local rule engine + smart UX + deception technology is sufficient to detect, warn, block, and counter-trace phishing attacks in real time.
